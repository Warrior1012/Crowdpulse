Privacy Policy

Prototype build, last updated September 2026
This is a hackathon prototype, not a deployed product. This page describes what the running demo actually does with data, not a hypothetical production version.

What this prototype collects

  • Zone density readings from the simulated IoT feed (synthetic data, not real people).
  • Attendee coordinates you type in or select on the map in the Attendee app tab. There is no real device GPS integration in this build; nothing is read from your phone or browser's location sensor.
  • Unsafe reports submitted through the "Report unsafe conditions here" button, tied to whatever coordinates were entered at the time.
  • Incident logs generated by the alert, dispatch, and bottleneck-detection engine while the server runs.

Where it's stored

Everything lives on the machine running the backend. Live state is kept in memory; incident history is appended to a local file at backend/data/incidents.log.jsonl. Nothing is sent to a third-party server, analytics provider, or cloud service. Stopping the server and deleting that file removes the data.

What a real deployment would need to add

Before this could run at an actual event, it would need: informed consent for location tracking, a defined retention period for incident logs, encryption in transit and at rest, and a named data controller responsible for attendee data under applicable law (for example, India's Digital Personal Data Protection Act). None of that is implemented in this prototype, and it should not be used with real attendee data as-is.
